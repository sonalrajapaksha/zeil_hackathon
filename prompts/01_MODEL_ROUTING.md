# Modular model routing

Use fast/cheaper available model for tasks 01, 03, 05, 09 docs and polish, strong reasoning for 02, 04, 06, 10, 11, 12 and optional 13; UI-focused model with Impeccable for 07. Escalate a blocker after two failed scoped attempts. A better model used on hard integration is usually more efficient than many weak agents. Model permissions are client-specific, never assume plan supports a model name.

At start of each Codex conversation paste: “Read AGENTS.md, docs/MASTER_SPEC.md, docs/BONUS_CHALLENGES.md, docs/PROGRESS.md, then run task NN from prompts/tasks/, respecting dependency gate and file ownership. Report tests and update docs.”

At end: files touched, validation actually run, proof for relevant bonus, blockers, next task prompt, commit hash. Main integrator owns shared contracts, server routes and deployment. Secondary UI agent touches isolated components only; do not compete on same files.
